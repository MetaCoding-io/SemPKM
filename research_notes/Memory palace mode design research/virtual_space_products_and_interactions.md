# 2D virtual-space / "walkable world" products: how they attach actions, content and tools to places

Research date: 2026-11-03. Scope: real products' interaction patterns (what an avatar entering a zone, approaching an object or pressing an interact key triggers), how web content is embedded, how spaces are authored, and what worked / what users complained about. Written for the SemPKM "memory palace" mode design (walk an avatar to the Study -> open a research dashboard; walk to the Library -> show a media collection).

A recurring vocabulary used below for each pattern:
- **Trigger**: enter zone / proximity / press key / click / timed.
- **Response**: side iframe ("co-website"), modal, popup at a map rectangle, bottom-of-screen action message, teleport, camera change, ambient (audio, highlight), new browser tab.
- **Stays in-world?**: whether the result overlays the map (avatar still visible) or jumps out to a normal web UI.

## Key Question 1: WorkAdventure — zones, openWebsite / co-websites, Jitsi, silent zones, focusable areas, Map Scripting API, map format; and what the gamebreaking.com post actually describes

### Takeaway
WorkAdventure's whole interaction model is "rectangular area + properties": an area object in a Tiled map (or drawn in the inline editor) carries properties such as `openWebsite`, `silent`, `playAudio`, `jitsiRoom`, `exitUrl`, and the client reacts when the avatar's position enters the rectangle. Content opens as an iframe panel docked to the right side of the screen ("co-website"), with a tab per open site, and the trigger can be immediate-on-enter, "press SPACE" (`onaction`) or "click an icon" (`onicon`). A JavaScript Scripting API (`WA.*`) lets a map author subscribe to area enter/leave events and open co-websites, popups anchored to map rectangles, modals, banners, fixed-position UI iframes, action-bar buttons, play sounds/videos, show/hide layers, change tiles, and teleport. The gamebreaking.com post is not about WorkAdventure at all: it is a game studio's account of running a "real-time remote" culture inside Gather (proximity voice/video, private desks and meeting rooms, "press F for confetti"), and it does not describe content embedding.

### Cited Findings

**The gamebreaking.com "real-time remote" post**
- The post (by Dru Erridge, Gamebreaking Studios) describes moving from async remote work to a "real-time remote" workplace built on Gather, a 2D virtual office on the web; the author explicitly says it "isn't an ad for Gather." They had also tried Google Meet, Discord muted "hangout" calls and Mozilla Hubs, and rejected Hubs over cross-talk, fatigue and performance. — [gamebreaking.com](https://www.gamebreaking.com/posts/real-time-remote)
- Interaction model described: "It has proximity voice/video and private spaces for desks and meeting rooms." Walking to someone's desk is how a conversation starts; avatar position is social signalling (standing at a desk = "Can I come in?", sitting in an AFK stall = "I'll be back later"); pressing F throws confetti, which the author calls "actually pretty important." — [gamebreaking.com](https://www.gamebreaking.com/posts/real-time-remote)
- The post does not explain how external tools or content are embedded in the space; it only mentions a floor-plan expansion in 2022 and team photos. Supporting practices: core hours 8:30–15:00 PT, annual retreats, hiring within overlapping time zones, focus hours and fewer recurring meetings. Key lines: "Having a simulated environment gave us access to more of the shorthand"; "Quicker turn-around beats higher throughput"; "Async work can be successful in the right environment, but you have to want decoupled schedules and written communication as badly as we want spontaneity and live collaboration." — [gamebreaking.com](https://www.gamebreaking.com/posts/real-time-remote)

**WorkAdventure area properties (Tiled editor)**
- Zones are Tiled objects of class `area` (layers also work but area objects are recommended for performance). Silent zone: boolean `silent` — users inside cannot hear each other even when adjacent. Audio zone: `playAudio` (MP3 URL, relative allowed), `audioLoop` (bool), `audioVolume` (float 0–1; the player uses min(this, user's last chosen volume)); `playAudioLoop` is deprecated; the file must be served with CORS headers. The docs recommend the inline map editor over Tiled for these. — [docs.workadventu.re special zones](https://docs.workadventu.re/map-building/tiled-editor/special-zones)
- `openWebsite` (string, must start with `https://`): opens the URL as an iframe on the right side of the screen. `openWebsiteWidth` (0–100, iframe width); `openTab` (open in a new browser tab instead of the iframe); `openWebsiteClosable` (bool); `openWebsiteTrigger`: unset = opens as soon as the user enters the zone, `onaction` = user must press SPACE and a message appears at the bottom of the screen, `onicon` = an icon appears at the bottom of the screen and the user clicks it; `openWebsiteTriggerMessage` customises the prompt (default "Press on SPACE to open the web site"); `openWebsitePolicy` is passed straight to the iframe `allow` attribute (e.g. `fullscreen`), since iframes otherwise have limited rights such as no webcam; `openWebsiteAllowApi` (bool) lets the embedded site talk back to WorkAdventure via the scripting API. Several co-websites can be open at once, each with its own tab in the right panel. — [docs.workadventu.re opening a website](https://docs.workadventu.re/map-building/tiled-editor/opening-a-website)
- Embedding limits: sites that send `X-Frame-Options` cannot be loaded; a regular YouTube page cannot be embedded, use the Share > Embed URL; embedded sites that need cookies must set `SameSite=none` or login fails. — [docs.workadventu.re opening a website](https://docs.workadventu.re/map-building/tiled-editor/opening-a-website)
- Entry/exit: a layer named `start` (or any layer with boolean `startLayer`=true) holds spawn tiles; a `start` string property on a tile names an entry point. An exit is a layer with an `exitUrl` property (relative or absolute map URL); reaching any tile on it leaves the scene; `exitSceneUrl`/`exitInstance` are deprecated. A map URL can carry `#entry-point-name` to spawn at a named entry point, and `#start&moveTo=meeting-room` auto-walks the player to a layer/object/coordinates after spawning. The map is "a JSON file hosted at a URL" (e.g. `https://example.com/my/map.json`). — [docs.workadventu.re entry-exit](https://docs.workadventu.re/map-building/tiled-editor/entry-exit)
- Older (2021) scripting docs mirrored in community forks: zones were defined with a `zone` property on a layer and hooked with `WA.onEnterZone`/`WA.onLeaveZone`; "A player passing over a zone opens a website as an iframe on the right side of the screen"; a popup needs a rectangle object on an object layer to position it. — [kraut.space mirror of scripting.md](https://git.kraut.space/Kraut.World/server/src/commit/9a8b10bbf5c9ac178fc0b5bc767ea8ee1cb18837/docs/maps/scripting.md)

**WorkAdventure inline (in-app) area editor**
- Area property types available in the inline map editor: Start/Exit; Open a link; Podium/Audience zone (also called Podium/Stage/Presentation Zones); Meeting room; Silent zone; Focusable zone; Play a sound; Restricted area; Personal area; Lockable area; Maximum users; Matrix chat zone; Highlight; Jitsi meeting (deprecated). A separate "Open document" property page and a Megaphone page also exist. Multiple "Play sound" and "Open a link" actions can be attached to one area. Areas are created by clicking the map or selecting a zone, resized via border handles, deleted via trash icon or Delete key. — [docs.workadventu.re area editor](https://docs.workadventu.re/map-building/inline-editor/area-editor)

**WorkAdventure Map Scripting API (`WA.*`)**
- Room events: `WA.room.onEnterLayer(name)` / `WA.room.onLeaveLayer(name)` and `WA.room.area.onEnter(name)` / `WA.room.area.onLeave(name)`; callbacks receive a `reason` of `"initial"` or `"move"` (a subscription made while already inside fires immediately with `"initial"`). Also `WA.room.showLayer` / `hideLayer`, `WA.room.setProperty(layerName, propertyName, value)`, `WA.room.area.create({name,x,y,width,height})` / `get` / `delete`, `area.setProperty`, `WA.room.getTiledMap()` (returns the parsed Tiled JSON), `WA.room.setTiles(...)` (change tiles at runtime), `WA.room.loadTileset(url)`, and `WA.room.website.create({url, x, y, width, height, ...})` which places an iframe *inside the map world* (an `EmbeddedWebsite` with `url, visible, allow, allowApi, x, y, width, height, origin, scale`). — [docs.workadventu.re api-room](https://docs.workadventu.re/developer/map-scripting/references/api-room)
- UI API: `WA.ui.openPopup(targetObject, message, buttons[])` shows a message + button row anchored to a Tiled rectangle object (button classes normal/primary/success/warning/error/disabled); `WA.ui.displayActionMessage({message, callback, type})` shows a bottom-of-screen message dismissed with SPACE which runs the callback; `WA.ui.actionBar.addButton(...)` adds buttons to the action bar (locations `top`, `appsMenu`, `buildMenu`, `profileMenu`); `WA.ui.modal.openModal({src, title, allow, allowApi, position: center|left|right (default right), allowFullScreen, closeCallback})` opens an iframe side/center panel with close and fullscreen buttons (full screen on mobile); `WA.ui.banner.openBanner({id, text, bgColor, textColor, closable, timeToClose (default 120000 ms), link})`; `WA.ui.website.open(...)` shows an iframe fixed to the browser viewport (does not scroll with the map), positioned by `vertical` top/middle/bottom and `horizontal` left/middle/right with CSS-unit size/margins; `WA.ui.registerMenuCommand(...)` adds a menu item that runs a callback or opens an iframe; `WA.ui.onRemotePlayerClicked` adds entries to the right-click menu on other avatars; `WA.ui.playVideo(url, {loop, name, avatar})` plays a video "like a talking participant". — [docs.workadventu.re api-ui](https://docs.workadventu.re/developer/map-scripting/references/api-ui)
- Navigation API: `WA.nav.openCoWebSite(url, allowApi?, allowPolicy?, percentWidth?, position?, closable?, lazy?)` returns a `CoWebsite` (close with `coWebsite.close()`), opens "in an iFrame (on the right side of the screen)", `percentWidth` is clamped to a maximum of 70% of viewport, `position` picks the slot; `WA.nav.getCoWebSites()`; `WA.nav.openTab(url)` (new browser tab); `WA.nav.goToPage(url)` (fully unloads WorkAdventure and navigates); `WA.nav.goToRoom(url)` (switch to another map, or `"#my-entry-point"` to teleport within the current map). — [docs.workadventu.re api-nav](https://docs.workadventu.re/developer/map-scripting/references/api-nav)

### Inferences
- WorkAdventure effectively gives three "arrival modes" for a place: (a) auto-open on enter (good for ambient/low-cost content like audio, a dashboard that should just appear), (b) `onaction` "press SPACE" (good for heavier content the user should opt into, mirrors Gather's "press x"), (c) `onicon` (a passive affordance that does not interrupt walking). A memory-palace design can adopt these three as a per-place setting.
- The right-docked co-website panel (max ~70% width, tabbed, closable) keeps the avatar visible and is the default "stay in-world" pattern; `openTab`/`goToPage` are the explicit "jump out to the normal web UI" escape hatches. `WA.room.website.create` (iframe placed on the map at world coordinates) is the only truly in-world embedding; it is rarer and more fragile.
- The separation between the static Tiled JSON (geometry, tilesets, area objects with properties) and the dynamic Scripting API (JS referenced from the map that reacts to enter/leave) is a good template for SemPKM: a declarative place→action binding stored in the graph, plus an optional scripted hook.
- Property-naming in WorkAdventure (`openWebsite*`, `playAudio`, `silent`, `exitUrl`, `start`) is a ready-made vocabulary for a "place properties" schema.

### Gaps
- The focusable-zone page returned 404 at the URL tried (`/map-building/tiled-editor/focusable-zones`); the inline-editor index confirms a "Focusable zone" type exists but I could not document its properties (e.g. `focusable`, `zoom_margin`) or camera behaviour from a live page.
- I did not fetch the pages for Jitsi/meeting rooms (`jitsiRoom` etc.), Podium/Audience zones, Personal/Lockable/Restricted areas, Matrix chat zones, "Open document" or the Klaxoon/Google Docs/Eraser/YouTube integration pages; the inline-editor index lists them but not their behaviour.
- No documentation fetched describes the newer WAM map file format (the companion file to the Tiled `.tmj` used by the inline editor); only the Tiled JSON hosting model is confirmed.
- The maximum number of simultaneous co-websites is not stated on the pages read.

## Key Question 2: Gather (gather.town) — embedded objects, press-x prompts, tile effects / private spaces, map maker, templates, and why usage declined after 2022

### Takeaway
Gather models interactivity as objects placed on a 32×32 tile grid: decorative objects do nothing; "interactive" objects show a prompt (default `Press "x" to interact.`) when the avatar is within activation distance and, on x, open an embedded website / image / video (YouTube, Twitch, Vimeo) inside a Gather iframe, a note, or an external call (Zoom/Webex/Teams in a new window). Space-level behaviour comes from five tile effects: Impassable, Spawn, Portal, Private Area, Spotlight. The category shrank when offices reopened in 2022: Gather laid off about a third of staff in July 2022, cut the free tier from 25 to 10 users in Feb 2023 and reportedly removed it in Sept 2025; competitors Teamflow, Wonder and Skittish shut down; one analyst piece says Gather's remote-work product is profitable but "not venture scale". Reviewers' main complaints are reliability (voice drops, editor changes not saving), performance, and a steep learning curve for map editing.

### Cited Findings

**Objects and interaction**
- Gather objects are "Decorative" (furniture, plants, food — no interaction) or "Interactive" ("Provide embedded media or other functionality when the user presses x"). Interactive types: **Embedded Website** ("Link to any embeddable website directly inside a Gather iframe"); **Embedded Image** (.png/.jpeg/.gif shown in an iframe); **Embedded Video** (YouTube, Twitch, Vimeo incl. playlists and live streams); **External Call** ("Call will open in new window and auto-mute in Gather", Zoom/Webex/Teams); **Note Object** (lines of text or links that open in a new window). Most objects have no interaction by default except Games, Sound and a few specials such as the whiteboard. Custom images can be uploaded; tiles are 32×32 px; there is no object-count limit, only a total map-size limit. — [Gather Objects Overview](https://support.gather.town/hc/en-us/articles/15910376994708)
- Advanced options: **Prompt message** default `Press "x" to interact.` with custom text allowed; **Object image** and **Active image** (the image swaps "once they're within the activation distance"); **Loading icon** for embedded websites (default is the spinning Gather grapes logo); **Caption** for embedded images (shown via an "i" icon when the expanded image is open); **Synchronized start time** for embedded videos so everyone sees the same frame (black screen before start; not for live streams). "Display (start)" / "Display (end)" options were removed. — [Gather Object Advanced Options](https://support.gather.town/hc/en-us/articles/15910418059796)
- Third-party notes: embedded website URLs must be HTTPS or they will not load — [dev.classmethod.jp](https://dev.classmethod.jp/articles/gather-town-integration-with-embedded-websites/); sites that block framing are instead opened in a new tab — [uni-tuebingen.de Gather guide](https://uni-tuebingen.de/de/226704); interactive objects are typically highlighted with a glowing yellow outline when in range — [CHItaly Gather guide](https://fmor.notion.site/CHItaly-Gather-Town-380d89f56a4e41668afa70afdd501c15).

**Tile effects (space-level behaviour)**
- Gather's guide lists five tile effects: **Impassable** (walls, statues), **Spawn** (random among several; map centre if none), **Portal** (moves the avatar to another location; Mapmaker docs say to place a portal in both rooms linking back), **Private Area** (people on tiles sharing the same Area ID can talk privately), **Spotlight** (anyone standing on it broadcasts audio/video/chat to the whole map). — [Gather Tile Effects Overview](https://support.gather.town/hc/en-us/articles/15910385115412); [Drexel Mapmaker – Tiles](https://support.cci.drexel.edu/remote-conferencing-and-class-capture/gather-town/mapmaker-tiles/); the Korean Gather-like platform ZEP documents the same five effects and notes a portal can fire automatically when stepped on — [ZEP tile effect guide](https://docs.channel.io/zep-guide/en/articles/Tile-Effect-Guide-0e64e720)
- Custom maps are built in Gather's Mapmaker (custom map overview) — [Gather Custom Map Overview](https://support.gather.town/hc/en-us/articles/15910430385172)

**Decline and status**
- Gather laid off roughly a third of its staff in mid-2022 (citing TechCrunch, 1 July 2022); the category "collapsed as offices reopened in 2022"; Teamflow later shut down; the founding teams of Gather and Kumospace moved on; the analyst says Gather said in Feb 2026 its remote-work product was profitable and growing but "not venture scale", spun out as an independent business with part of the team joining Figma — [Sacra, "Virtual Office Collapse and Pivot"](https://sacra.com/chat/h/f1c1c17b-9051-46ec-aa14-6cd94e3aec7d/). I could not find a second source for the spin-out/Figma claim (see Gaps).
- Free tier cut from 25 to 10 concurrent users effective 21 Feb 2023 (announced by Japanese partner LocalSquare) — [ascii.jp](https://ascii.jp/elem/000/004/125/4125579/)
- A competitor guide (SoWork, marketing content) says Gather discontinued its free tier in September 2025, now charges $15/user/month ($12 annual), and that "Gather 2.0" (Sept 2025) was followed by audio complaints (popping, freezing, dropped calls), performance issues and a steep map-editing learning curve — [sowork.com](https://www.sowork.com/blog/best-gather-town-alternatives-remote-teams). Treat as non-independent.
- Product Hunt's summary of 10 reviews: main complaints are reliability — voice chat failing in meeting rooms and editing bugs that stop changes from saving; otherwise positive — [Product Hunt Gather reviews](https://www.producthunt.com/products/gather-town/reviews)
- An EA Forum post about a shared Gather instance reports almost all paid capacity went unused because usage clustered around weekly meetings — [EA Forum](https://forum.effectivealtruism.org/posts/ueQgG8tahDyDhjCHw/consider-using-the-ea-gather-town-for-your-online-meetings)
- A TrustRadius reviewer said their use of virtual conferences fell after the pandemic emergency ended in May 2023 — [TrustRadius](https://www.trustradius.com/products/gather-video-chat)
- Status page records a ~4-hour audio/video outage on 28 Nov 2023 — [isdown.app](https://isdown.app/status/gather/incidents/242315-audio-and-video-is-dropping-for-some-users)
- Kumospace bought a virtual-office rival in Aug 2023 (consolidation) — [Bloomberg](https://www.bloomberg.com/news/articles/2023-08-16/kumospace-buys-virtual-office-software-rival)

### Inferences
- Gather's object model is essentially "sprite + prompt + payload type (website/image/video/note/call)". That is a minimal, proven schema for binding a knowledge object to a place: SemPKM could map Note → note object, media Concept → embedded video/image, dashboard → embedded website, Person → external-call-like action.
- The "Active image" swap and yellow highlight at activation distance is the standard affordance telling the walker "this spot does something" before they commit; a memory palace needs the same pre-interaction cue, otherwise places feel dead.
- Private Areas and Spotlights have no direct single-user analogue, but "Private Area ID" is structurally identical to a "room" concept: a set of tiles sharing an ID → one context (one dashboard, one collection).
- The decline evidence suggests the *social presence* value proposition was tied to the pandemic; the *spatial content layout* value (walking to a place to find things) was never the primary draw for these products and remains comparatively unexplored for personal use.

### Gaps
- No independent 2023-era retrospective on Gather's decline was found; Sacra is the only analysis piece, and its Feb 2026 spin-out/Figma claim could not be corroborated by a second search.
- Nothing authoritative found about "Gather 2.0" (Sept 2025) or changes to the map maker; only a competitor blog mentions it.
- Activation-distance value (in tiles) is not stated in the official help pages read.
- No Hacker News threads about Gather fatigue surfaced via web search; sentiment there remains unverified.

## Key Question 3: Other 2D/3D virtual-space products — Teamflow, Kumospace, SpatialChat, Skittish, Mozilla Hubs, Topia, Sococo, Pixelverse, Wonder.me, Branch, ZEP; which are alive in 2026

### Takeaway
Most pandemic-era spatial-presence products are dead or hollowed out: Skittish closed 14 Dec 2022 (its spatial-audio API provider High Fidelity shut down with six weeks' notice), Wonder.me shut down (reasons undisclosed, pointing users to Kumospace), Teamflow shut down, Mozilla Hubs ended 31 May 2024 (code handed to the Hubs Foundation). Still listed as operating in 2026 directories: Gather, Kumospace (founders have pivoted to an AI company), Sococo (owned by IgniteTech), SpatialChat (video circles on a canvas), Topia (2D worlds for events/education), SoWork, Flat.social, and ZEP (Korea). Pixelverse and Branch: no evidence found.

### Cited Findings
- **Skittish** (Andy Baio's browser-based, audio-first, animal-avatar event space): wound down October 2022 after High Fidelity ended the spatial audio API it depended on with six weeks' notice and demand for virtual events dropped; closed permanently 14 Dec 2022 — [waxy.org, "Winding Down Skittish"](https://waxy.org/2022/10/winding-down-skittish); [skittish.com notice](https://new.skittish.com/2022/winding-down-skittish/); Skittish was described by Discourse as "a playful, audio-first space for virtual events and gatherings" — [blog.discourse.org](https://blog.discourse.org/2021/09/skittish/)
- **Wonder.me**: shut down; reasons not disclosed; Wonder's own post pointed users to Kumospace — [Kumospace on Wonder shutdown](https://www.kumospace.com/blog/wonder-shutdown); alternatives roundup — [Veertly](https://blog.veertly.com/wonderme-shutdown-alternatives)
- **Teamflow**: shut down (no date given); Kumospace published a "Teamflow shutdown" post — [Kumospace](https://development.kumospace.com/blog/teamflow-shutdown); Sacra: "Teamflow shut down" as offices reopened — [Sacra](https://sacra.com/chat/h/f1c1c17b-9051-46ec-aa14-6cd94e3aec7d/)
- **Kumospace**: still marketed in 2026, but cofounders Brett Martin and Yang Mou now focus on Fonzi AI and day-to-day Kumospace work was handed off — [Sacra](https://sacra.com/chat/h/f1c1c17b-9051-46ec-aa14-6cd94e3aec7d/); 2026 alternatives pages treat it as current — [katmaitech](https://katmaitech.com/alternatives/kumospace-alternatives)
- **Mozilla Hubs** (3D WebXR rooms): Mozilla ended support 31 May 2024; no new subscriptions, demo server or Hubs Cloud; codebase now maintained by the Hubs Foundation; Mozilla open-sourced its avatars/scenes — [hubs.mozilla.com/labs/sunset](https://hubs.mozilla.com/labs/sunset); [Road to VR](https://roadtovr.com/mozilla-hubs-shutdown-web-xr/); community edition continues — [ryanschultz.com](https://ryanschultz.com/?term_id=24)
- **Topia**: listed in a 2026 directory as "Accessible 2D virtual worlds for events and education", free up to 50 visitors, supporting up to 2,000 — [flat.social metaverse resources](https://flat.social/blog/metaverse-resources)
- **Sococo**: "enterprise virtual office acquired by IgniteTech. Up to 1,000+ users"; listed in Feb 2026 roundups — [fitgap](https://us.fitgap.com/search/virtual-workspaces/collaborative); [sowork comparison](https://www.sowork.com/alternatives/sococo-vs-sowork)
- **SpatialChat**: "participants appear as video circles on a shared canvas"; still listed in 2026 — [flat.social best virtual office tools](https://flat.social/blog/best-virtual-office-tools); [omr.com alternatives](https://omr.com/en/reviews/product/spatialchat/alternatives)
- **ZEP** (Korean Gather-like platform) documents the same five tile effects as Gather and its editor guide is public — [ZEP floor tile effects](https://docs.channel.io/zep-guide/en/articles/994ee502-Explore-FloorTile-Effects)
- **Roam** is cited as the direction the surviving category is taking: a virtual HQ only survives "inside a broader work stack" of meetings, chat, recordings and follow-ups (Sacra report titled "$4M/year Discord for work") — [Sacra](https://sacra.com/chat/h/f1c1c17b-9051-46ec-aa14-6cd94e3aec7d/)

### Inferences
- The products that died were pure presence layers whose value evaporated when co-presence stopped being scarce. Products that persist either bundle other work tooling (Roam, Kumospace) or serve events/education (Topia). For a single-user memory palace, the social-presence lesson is mostly negative: the spatial layer needs intrinsic value (recall, overview, ritual) rather than relying on other people being there.
- Skittish's failure shows the fragility of depending on a third-party real-time service; a self-hosted PKM "palace" avoids that class of risk entirely by having no live audio/video.

### Gaps
- No evidence found on Pixelverse or Branch (branch.gg) status in 2026.
- Status claims for Topia, Sococo and SpatialChat come from directories and competitor blogs, not from the vendors' own announcements.
- Teamflow's shutdown date and reason were not found.

## Key Question 4: Game-world productivity apps (tasks/notes/focus rendered as a room, town or pet) and virtual bookshelf / media-library apps

### Takeaway
A thriving indie niche renders productivity tools *as* a cozy room: Spirit City: Lofi Sessions (Steam, April 2024; to-do list, timer, habit tracker, journal, decoratable room, "Overwhelmingly Positive" with ~8.8k reviews), Mini Cozy Room: Lo-Fi (room decoration + desktop memos, to-dos, Pomodoro), Occult Office: Lofi Rituals (pixel-art calendar, to-dos, mood tracking, journalling, focus time), Ithya: Magic Study. Classic gamified trackers (Habitica RPG, Forest trees, Finch pet) reward tasks with growth but do not map tasks onto walkable space. Virtual-bookshelf cataloguing apps (Delicious Library, now discontinued; Libib; Bookshelf; Book Tracker) show that users value a *visual shelf of covers* and barcode/ISBN ingestion, and that discontinuation of the most "graphic" one (Delicious Library) left a gap reviewers notice.

### Cited Findings
- **Spirit City: Lofi Sessions** (Mooncube Games) has been on Steam since April 2024; a "gamified focus tool" with to-do list, timer, habit tracker and journal set to a lofi soundtrack; players "curate their own cozy virtual space"; Steam reviews Overwhelmingly Positive (8,817 English reviews at time of search) — [Steam](https://store.steampowered.com/app/2113850/Spirit_City_Lofi_Sessions/); press release on spirits (collectible creatures) — [Game Developer press release](https://www.gamedeveloper.com/press-release/check-out-the-lineup-of-cute-cuddly-new-spirits-in-upcoming-cozy-game-and-focus-tool-spirit-city-lofi-sessions-); launch press release — [gamespress](https://gamespress.westeu-v2.propressroom.com/Moocube-Games-Launches-the-Cozy-and-Chill-Gamified-Productivity-Tool-S)
- **Mini Cozy Room: Lo-Fi** pairs Lo-Fi music with room decoration and adds avatars, pets, desktop memos, to-do lists and a Pomodoro timer — [Steam](https://store.steampowered.com/app/3511030/LoFi/)
- **Occult Office: Lofi Rituals**: "colorful and lovingly handcrafted pixel art world with a calendar, to-do lists, mood tracking, journalling and focus time" — [Deku Deals](https://www.dekudeals.com/items/occult-office-lofi-rituals)
- **Ithya: Magic Study** is a "cozy background app combined with productivity tools" — [gameaton similar games](https://www.gameaton.com/game/spirit-city-lofi-sessions)
- **Habitica**: gamified habit tracking that "turns goals into an RPG adventure", with a free tier — [Headway Habitica alternatives](https://makeheadway.com/blog/habitica-alternatives); **Forest**: focus timer where you grow virtual trees (pricing reported inconsistently across sources) — [toolradar Forest vs Habitica](https://toolradar.com/compare/forest-vs-habitica); **Finch** is a self-care pet app rather than a productivity tool (no Pomodoro/focus mode/app blocking) — [habi.app Finch alternatives](https://habi.app/insights/finch-alternatives/)
- **Delicious Library 3** (Mac) is listed as Discontinued; alternatives listed include GCstar, Tellico, Kavita, Where Is It?, LibraryThing — [AlternativeTo](https://alternativeto.net/software/delicious-library); a reviewer who switched to **Book Tracker** notes it pulls cover art from Amazon and Open Library, supports barcode readers and CSV import, but "the interface isn't quite as graphic as the virtual bookshelf in DL" — [thedesignersassistant.com](https://thedesignersassistant.com/?p=3167)
- **Libib** catalogues home libraries by barcode scan, ISBN or manual entry; web + mobile, freemium — [freepressjournal](https://www.freepressjournal.in/amp/weekend/6-apps-to-help-manage-and-catalogue-your-home-library-virtually); **Bookshelf – Your virtual library** (iOS) organises books on multiple virtual bookshelves — [AlternativeTo](https://alternativeto.net/software/bookshelf--your-virtual-library); self-hosted **MyBibliotheca** is a personal library manager and reading tracker — [selfhostyourself](https://selfhostyourself.com/alternative-to/librarything-libib)

### Inferences
- The cozy-room apps succeed by making the *room itself* the dashboard: the timer, to-do list and journal are furniture-like objects you click, and decoration is the reward loop. Trigger is click (mouse), not avatar walking; response is an in-world panel. This is the closest commercial analogue to "the Study opens my research dashboard".
- The bookshelf apps show the "Library room" should render a shelf of covers (books, ebooks, videos) with status (want-to-read/watched), since cover-art shelves are the feature users mourn when products die.
- Habitica/Forest/Finch demonstrate that *growth/decay visuals* (trees, pets, levels) tied to task completion are sticky; a palace could let rooms "grow" as a project advances, but this is reward layering, not spatial navigation.

### Gaps
- I did not find any app that renders an arbitrary to-do list or note set as a *walkable* room/town where walking (rather than clicking) triggers the tool — the cozy-room apps are click-driven scenes.
- Tabby Cat and other tab/bookmark-gamifying extensions: not researched (no tool budget left); Plex/Jellyfin "walls", Steam, Backloggd, Goodreads shelves: not specifically researched beyond the bookshelf-app roundups above.
- "Cozy Grove", "Virtual Cottage", "Tiny Glade" used for focus: not researched.

## Key Question 5: Game-style UI for non-game information (dashboards, files, processes, portfolios as game maps)

### Takeaway
There is a long tradition of mapping system information onto game worlds — psDooM renders Unix processes as Doom monsters you shoot to renice/kill (2000s, GPL; forks psdoom-ng and a 2026 Textual-based terminal PSDoom exist) — and a large hobbyist genre of RPG/Pokémon-style portfolio sites where walking an avatar to NPCs/objects opens dialog boxes or project panels, usually with a conventional site kept alongside because visitors "99% of the time" just want the quick view. Open-source engines (Kaplay.js + React with JSON-driven content) make the pattern cheap to build.

### Cited Findings
- **psDooM**: "a process monitor and manager for *nix systems ... a graphical interface to the 'ps', 'renice', and 'kill' commands"; processes appear as enemy bots, shooting renices, killing sends `kill -9`; based on XDoom, GPL-2.0 — [psdoom.sourceforge.net README](https://psdoom.sourceforge.net/docs/README); [project page](https://psdoom.sourceforge.net/); fork **psdoom-ng** ("first-person shooter operating system process killer" on Chocolate Doom) — [GitHub keymon/psdoom-ng](https://github.com/keymon/psdoom-ng); a separate Python/Textual terminal **PSDoom** process manager — [PyPI psdoom](https://pypi.org/project/psdoom/0.1.1/); write-up — [Lunduke](https://lunduke.substack.com/p/linux-process-monitoring-with-doom)
- **RPG-style portfolios**: a Pokémon-like JavaScript game used as the base for an interactive résumé — [dev.to pfilaretov42](https://dev.to/pfilaretov42/how-to-build-your-interactive-resume-in-4-simple-and-2-easy-steps-570l); an open-source "data-driven 2D RPG portfolio engine built with React, Kaplay.js, and Jotai" where content is swapped via JSON and 4/8-direction sprite sheets are supported — [GitHub VeroSedai/portfolio-gamified](https://gh.hhj520.top/VeroSedai/portfolio-gamified); a top-down RPG site where "tapping each character ... trigger[s] a traditional RPG-styled dialog box" — [dev.to justdude](https://dev.to/justdude/turning-my-resume-into-an-interactive-game-reactjs-go-4chd); a pixel-art room where "You can walk through my room, interact with the objects around you" — [dev.to mewmewdevart](https://dev.to/mewmewdevart/i-built-a-retro-gamified-portfolio-yes-with-pixel-art-games-windows-95-vibes-589k); a scroll-driven walk through five chapters with day turning to night — [dev.to endigo9740](https://dev.to/endigo9740/my-new-portfolio-3ke6); **CV Crossing**, an Animal-Crossing-inspired 3D résumé village with WebMCP tools for walking and visiting milestones — [mcpmarket CV Crossing](https://mcpmarket.com/server/cv-crossing); one author keeps a conventional portfolio because people use it "99% of the time when they just want to quickly see my work" — [dev.to svet_62385e9](https://dev.to/svet_62385e9/svetlinas-quest-a-gamified-portfolio-14bh)
- Creative Bloq coverage of a retro-game portfolio site — [Creative Bloq](https://www.creativebloq.com/javascript/portfolio-site-retro-gaming-twist-12121513)

### Inferences
- The consistent interaction grammar in these hobby projects is: walk up to an NPC/object → an RPG dialog box (bottom of screen) → optional "open project" that jumps to a normal web panel. This matches WorkAdventure's `displayActionMessage` + co-website pair and Gather's "press x" + iframe pair; three independent lineages converged on "approach → prompt → panel".
- The "keep a boring version too" advice is a strong signal for SemPKM: the palace should be an *alternate view* over the same graph, never the only way to reach content.
- psDooM's lesson is that mapping live system state to in-world entities (monsters = processes) is memorable but only useful when the mapping is semantically tight (shoot = kill). For a PKM, analogous tight mappings would be e.g. overdue tasks appearing as weeds in a garden room.

### Gaps
- "Minecraft as file system" and "Gather-based dashboards" were not researched (tool budget).
- Game UI pattern collections (gameuidatabase.com, Interface in Game) were not consulted; they would be the place to source concrete dialog-box / inventory / map-screen references.

Authoring approaches observed:
- **External tile editor + custom properties**: Tiled `.tmj/.json` with `area`-class objects carrying string/bool/float properties; map hosted at a URL; optional JS referenced from the map (WorkAdventure) — [docs](https://docs.workadventu.re/map-building/tiled-editor/opening-a-website)
- **In-app inline editor**: draw/select areas on the live map and pick typed property presets from a list (WorkAdventure Areas editor) — [docs](https://docs.workadventu.re/map-building/inline-editor/area-editor)
- **In-app object picker + tile-effect painter**: 32×32 grid, object categories, five tile effects, prompt text per object (Gather Mapmaker) — [Gather](https://support.gather.town/hc/en-us/articles/15910430385172)
- **JSON-driven content on a fixed engine**: swap content via JSON files; sprite sheets for avatars (Kaplay.js portfolio engine) — [GitHub](https://gh.hhj520.top/VeroSedai/portfolio-gamified)

What users complained about (across sources): reliability of audio/video and editor saves (Gather Product Hunt reviews); performance and a steep map-editing learning curve (competitor-sourced, weak); X-Frame-Options/HTTPS/cookie restrictions breaking embeds (WorkAdventure and Gather docs); dependence on third-party real-time APIs (Skittish); fatigue and cross-talk in 3D (Hubs, per gamebreaking.com); and, for game-style portfolios, visitors wanting the plain version most of the time.
