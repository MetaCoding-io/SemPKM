# S02: Compression & HTTP Caching — Research

**Date:** 2026-03-20
**Status:** Complete

## Summary

S02 is straightforward nginx configuration work. S01 already did the heavy lifting: content-hashed filenames, .gz pre-compressed siblings, and the `/assets/` location block with a placeholder comment `# Cache headers added in S02`. The work breaks into three clean units: (1) gzip compression config at the server level, (2) immutable cache headers on `/assets/`, and (3) ETag + no-cache headers on static HTML pages. All changes are in `frontend/nginx.conf` (and its demo counterpart `frontend/nginx.demo.conf`).

No new libraries, no backend code changes, no build pipeline changes. The only risk is getting the nginx directive ordering right (gzip directives go in the `server {}` block, cache headers go in individual `location` blocks).

## Recommendation

Three additions to nginx.conf:

1. **Server-level gzip** — `gzip on` with `gzip_types` covering text/html, CSS, JS, JSON, SVG, XML. This compresses proxied (dynamic) HTML responses from FastAPI. Set `gzip_min_length 256` to skip tiny responses. `gzip_vary on` for proper proxy/CDN behavior.

2. **`gzip_static on`** in the `/assets/` block — nginx will serve the pre-built `.gz` files from S01's build.js instead of compressing on-the-fly. Zero CPU cost for the most-requested files.

3. **Cache headers by location:**
   - `/assets/` → `Cache-Control: public, max-age=31536000, immutable` (content-hashed filenames = safe forever)
   - `/css/` and `/js/` → keep existing `no-store, no-cache` (dev-mode raw files, not served in production)
   - Auth HTML pages (`setup.html`, `login.html`, `invite.html`) → `Cache-Control: no-cache` with nginx's built-in ETag (automatic for static files when `etag on`, which is the default in nginx)
   - Proxied HTML responses → `Cache-Control: no-cache` added by the API backend or nginx `add_header` on the catch-all proxy block. ETag for proxied responses is out of scope for S02 (that's S04's backend cache headers).

The demo config (`nginx.demo.conf`) needs the same changes. It's a copy of nginx.conf with the read-only enforcement block added — all the same location blocks exist.

## Implementation Landscape

### Key Files

- `frontend/nginx.conf` — The only file that needs significant changes. Currently has `/assets/` block (from S01) with no cache headers, `/css/` and `/js/` with `no-store, no-cache`, and zero gzip configuration. All changes are additive.
- `frontend/nginx.demo.conf` — Mirror of nginx.conf with read-only enforcement. Needs identical compression and caching changes.

### What Exists From S01

- `/assets/` location block with `alias /srv/built-assets/;` — ready for `gzip_static on` and `Cache-Control: immutable`
- `.gz` pre-compressed files generated by `build.js` step 10 (gzip -k -9 on every .js, .css, .json in dist/)
- Content-hashed filenames in dist/ (e.g., `vendor-a1b2c3d4.min.js`)
- manifest.json mapping logical names to hashed filenames

### nginx Directives Needed

**Server block level (outside all location blocks):**
```nginx
# Compression for dynamic (proxied) responses
gzip on;
gzip_vary on;
gzip_proxied any;
gzip_comp_level 6;
gzip_min_length 256;
gzip_types
    text/plain
    text/css
    text/javascript
    application/javascript
    application/json
    application/xml
    image/svg+xml
    text/xml;
```

**`/assets/` location block:**
```nginx
location /assets/ {
    alias /srv/built-assets/;
    gzip_static on;
    add_header Cache-Control "public, max-age=31536000, immutable";
    try_files $uri =404;
}
```

**Auth HTML pages** — nginx automatically generates ETags for static files (the `etag` directive defaults to `on`). The current auth page locations don't have any Cache-Control headers. Adding `Cache-Control: no-cache` tells browsers to revalidate with If-None-Match (ETag), so repeat visits get 304 Not Modified instead of re-downloading. This is a minor optimization — auth pages are small.

```nginx
location = /setup.html {
    root /usr/share/nginx/html;
    add_header Cache-Control "no-cache";
    try_files $uri =404;
}
```
Same for `/login.html` and `/invite.html`.

**Proxied HTML responses** — The catch-all `location /` proxies to FastAPI. Adding `add_header Cache-Control "no-cache"` here is acceptable for the proxy response. However, `gzip on` at the server level already compresses these responses. ETag for proxied responses requires backend support (S04 scope).

### Build Order

1. **T01: nginx gzip + cache headers** — Add gzip directives to server block, immutable headers to `/assets/`, no-cache to auth pages. Update both nginx.conf and nginx.demo.conf. Verify with `nginx -t` inside Docker, then `curl -H "Accept-Encoding: gzip" -sI` checks.
2. **T02: Docker verification** — Rebuild frontend, start stack, verify with curl that (a) `/assets/vendor-*.min.js` returns `Content-Encoding: gzip` and `Cache-Control: immutable`, (b) auth HTML pages return ETag headers, (c) proxied HTML from FastAPI returns compressed. Quick browser test to confirm workspace still loads correctly.

This could reasonably be a single task — the scope is small and the verification is fast.

### Verification Approach

All verifiable via `curl` against the Docker stack:

```bash
# 1. Compression on hashed assets (gzip_static)
curl -H "Accept-Encoding: gzip" -sI http://localhost:3000/assets/vendor-HASH.min.js \
  | grep -E 'Content-Encoding|Cache-Control'
# Expected: Content-Encoding: gzip, Cache-Control: public, max-age=31536000, immutable

# 2. Compression on proxied HTML (gzip on)
curl -H "Accept-Encoding: gzip" -sI http://localhost:3000/browser/ \
  | grep Content-Encoding
# Expected: Content-Encoding: gzip

# 3. Auth page ETag + no-cache
curl -sI http://localhost:3000/login.html | grep -E 'ETag|Cache-Control'
# Expected: ETag: "...", Cache-Control: no-cache

# 4. Auth page conditional GET returns 304
ETAG=$(curl -sI http://localhost:3000/login.html | grep ETag | tr -d '\r')
curl -sI -H "If-None-Match: ${ETAG#ETag: }" http://localhost:3000/login.html | head -1
# Expected: HTTP/1.1 304 Not Modified

# 5. Dev-mode raw files still no-cache
curl -sI http://localhost:3000/js/workspace.js | grep Cache-Control
# Expected: Cache-Control: no-store, no-cache, must-revalidate

# 6. nginx config syntax valid
docker compose exec frontend nginx -t
# Expected: syntax is ok, test is successful
```

## Constraints

- `gzip_static on` requires the `.gz` sibling to be in the exact same directory as the original file with `.gz` appended. S01's build.js generates these correctly in `dist/` which gets copied to `/srv/built-assets/`.
- `nginx:stable-alpine` includes `ngx_http_gzip_module` and `ngx_http_gzip_static_module` in the default build. No custom compilation needed.
- The demo config (`nginx.demo.conf`) must stay in sync with `nginx.conf` — it's a manual copy with the read-only block added. Both files need identical compression and caching changes.
- `add_header` in nginx replaces (not appends to) headers from the same directive scope. The existing `Cache-Control: "no-store, no-cache, must-revalidate"` on `/css/` and `/js/` is correct for dev mode and should not be changed.

## Common Pitfalls

- **`gzip_static` and `add_header` interaction** — `gzip_static on` serves the `.gz` file directly, but nginx still needs the uncompressed file present to fall through `try_files`. Both files exist in dist/ (S01 generates both), so this is fine.
- **`gzip_proxied` must be set** — By default, nginx does NOT gzip responses from proxied backends. `gzip_proxied any` enables compression of all proxied responses (FastAPI HTML). Without it, the `location /` catch-all responses would be uncompressed despite `gzip on`.
- **nginx `add_header` inheritance** — `add_header` directives in a `location` block do NOT inherit from the parent `server` block. Each location must declare its own headers. This is already the pattern in the existing config.
